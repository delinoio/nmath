# NMath npm Package Contract

## Scope

This contract owns the `nmath-package` component of the [`nmath` project](project-nmath.md): the public npm package `@delinoio/nmath` at `packages/nmath/`.

## Runtime and Language

- ESM only. CommonJS consumers use dynamic `import()`. No CommonJS build is published.
- Node.js 24 only. Bun, Deno and browsers are out of scope.
- TypeScript sources with declaration output. Ordinary consumer type tests use TypeScript 7.0.2.
- The package loads the `nmath-node` native binary. If the prebuilt binary cannot load, import fails with `NMATH_NATIVE_LOAD`, the platform triple, the cause and manual source-build instructions. There is no automatic source build and no JavaScript computation fallback.

## Users and Operators

- JavaScript and TypeScript developers who use NMath from Node.js 24.
- `.nts` output produced by `nmath-compiler`, which imports `@delinoio/nmath/nts-runtime`.

When the `.nts` transform's extension-rewriting option is enabled, source-relative `.nts` specifiers in quoted imports and static template dynamic imports become `.js` specifiers. The [compiler contract](crates-nmath-compiler-contract.md) owns this behavior and its span mapping.

## Interfaces and Contracts

### Entry points

| Specifier                     | Entry point ID | Contents                                                                                                    |
| ----------------------------- | -------------- | ----------------------------------------------------------------------------------------------------------- |
| `@delinoio/nmath`             | `core`         | `createContext`, `NMathArray`, `Expr`, `slice`, `indices`, `mask`, dtypes, errors and arithmetic functions. |
| `@delinoio/nmath/numpy`       | `numpy`        | NumPy-style array creation, arithmetic, reductions, `matmul`, `random`.                                     |
| `@delinoio/nmath/pandas`      | `pandas`       | pandas-style `Series` and `DataFrame`.                                                                      |
| `@delinoio/nmath/polars`      | `polars`       | Polars-style `Series`, `DataFrame` and lazy frames.                                                         |

| `@delinoio/nmath/nts-runtime` | (internal)     | Helpers that compiled `.nts` output imports. Not documented for direct use.                                 |

The CLI executable is `nmath-compiler`. No separate compiler package is published. The package `bin` entry is a small Node.js launcher that runs the platform's prebuilt `nmath-compiler` executable from `native/` or the platform package; `@delinoio/nmath/compiler` runs the same executable with `--json`.
The compiler entry point, CLI launcher and compiler build script resolve or build the compiler without loading the numerical addon. A missing compiler reports compiler-specific recovery guidance. Numerical entry points still load the addon when imported.

### Contexts

```ts
const ctx = createContext({
  maxConcurrentJobs: 4,
  maxQueueLength: 64,
  cpuMemoryBudget: 1n << 30n,
  gpuMemoryBudget: 0n,
});
```

All four options are required. `ctx.close(): Promise<void>` follows the runtime close contract. `ctx.metrics()` returns measurement snapshots. Contexts and arrays implement `dispose()` and `Symbol.dispose` for `using`.
Native jobs release their execution slot before they settle their result Promise. Promise handlers can close the context or submit another job under the normal admission rules.

Array creation helpers (`ctx.array`, `ctx.full`, `ctx.zeros` and the NumPy `ones`, `full` and `arange` forms) check the CPU budget before they build JS or native input buffers and fail with `NMATH_MEMORY_BUDGET_EXCEEDED` when the input cannot fit. The context still makes the authoritative reservation when it creates the array.

Explicit and inferred dimensions in `ctx.array`, `ctx.full`, `ctx.zeros` and `ctx.generator(seed).random(shape)` must be finite integers from `0` through `4294967295`, inclusive. Their NumPy wrappers use the same rule. Invalid dimensions fail with `NMATH_SHAPE_MISMATCH` before budget arithmetic, input allocation or native shape conversion. Rank-zero shape `[]` and zero dimensions remain valid. A valid shape whose data length differs from its element count also fails with `NMATH_SHAPE_MISMATCH`.

### Expressions and compute

- Functions such as `add(a, b)` and methods such as `a.add(b)` return `Expr` without computing.
- `expr.compute({ device?: 'cpu' | 'gpu', signal?: AbortSignal }): Promise<Result>` runs one independent job.
- Results with rank 0 are JS scalars: `number` for floating and 32-bit-or-smaller integer dtypes, `bigint` for 64-bit integers, `boolean` and `string`. Complex values use the lossless `Complex` class. Other results are `NMathArray` values.
- Explicit lossy conversions: `toNumber()`, `toDate()`.
- Weak operand scalars follow NumPy NEP 50 with a fixed JS mapping: `number` acts as a Python `float`, `bigint` as a Python `int` and `boolean` as a Python `bool`. `Complex` acts as a Python `complex` weak operand.

Float16 arrays use `Float16Array` for numeric typed-array exchange when the Node.js 24 runtime provides it. Scalar reads return `number`. `ctx.arrayFromFloat16Bits(bits: Uint16Array, { shape? })` and `array.toFloat16Bits()` exchange exact IEEE-754 binary16 encodings, including NaN payloads. Both methods copy storage and preserve the existing budget and disposal rules. Numeric creation and `toTypedArray()` require `Float16Array`; they report an explicit error when it is unavailable. There is no float32 storage substitution. Public dtype promotion, reductions, casts and compiler helper signatures retain float16 where the runtime rules require it.

Small integer arrays exchange data through `Int8Array`, `Int16Array`, `Uint8Array` and `Uint16Array`. Scalar reads return `number`; signed and unsigned small-integer sums return `bigint`. Array-to-array promotion follows NumPy, including `int8` with `uint8` becoming `int16`, and `float32` with any 8-bit or 16-bit integer remaining `float32`.

`new Complex(real, imag = 0)` is the dedicated immutable complex scalar. `real` and `imag` are JS numbers and preserve both IEEE-754 components, including signed zeros and non-finite values. `item()`, nested `toArray()` output and rank-0 `compute()` results return `Complex` for complex dtypes. Implicit numeric conversion throws; `Complex.toNumber()` explicitly returns the real component and discards the imaginary component.

Complex array creation accepts nested `Complex` values or interleaved typed-array components in real/imaginary order. `complex64` requires `Float32Array`; `complex128` requires `Float64Array`. Typed input must contain an even number of components. Shape counts complex elements, not components. `toTypedArray()` returns an independent interleaved copy with the corresponding floating type. `full()` takes a `Complex` scalar and `zeros()` creates complex zero values.

Complex arithmetic, unary operations, reductions, indexing, writes, copies, explicit casts and 1-D/2-D matrix multiplication follow the runtime contract. Complex remainder is rejected by ordinary TypeScript declarations and by runtime expression validation. Complex GPU computation remains outside the GPU dtype subset.

The FFT entry point adds `fft2`, `ifft2`, `fftn`, `ifftn`, `fftshift`, `ifftshift`, `fftfreq` and `rfftfreq`. Multi-axis transforms compose the existing one-axis lazy nodes, so they inherit dtype, snapshot, budget, cancellation and GPU-rejection behavior. `fft2`/`ifft2` default to the final two axes; `fftn`/`ifftn` default to every axis. `s` supplies one positive length per transformed axis and makes the declared shape dynamic. `fftshift`/`ifftshift` keep dtype and shape; they accept all dtypes and default to every axis. `fftfreq`/`rfftfreq` take an explicit context and return `float64` arrays; the length must be a positive unsigned 32-bit integer and the sample spacing must be finite. The context charges these arrays like any other input.

### Typing

`NMathArray<D extends DType, S extends Shape>` and `Expr<D, S>` carry dtype and shape type parameters. `Shape` is a readonly tuple of `number` literals or `number` for a dynamic dimension. Broadcasting is computed at the type level for tuple shapes. Incompatible static shapes produce a type error; dynamic dimensions fall back to runtime validation without erasing dtype or rank.

The NumPy `sum`, `mean`, `min`, `max`, `prod`, `argmin` and `argmax` wrappers preserve the core methods' dtype and shape inference. Omitting the axis, or passing `undefined`, produces a scalar result type. A literal axis removes its dimension from a tuple shape. A dynamic axis retains the result dtype and uses a dynamic shape because its result rank is not known at type-check time. `prod` widens like `sum`; `argmin` and `argmax` use `int64`, so rank-0 index results are `bigint` and array results use `bigint` elements. The declarations reject string and temporal operands for products and index reductions, and runtime validation rejects them again with `NMATH_DTYPE_UNSUPPORTED`.

`sum`, `mean`, `min`, `max` and `prod` accept no axis, one axis or an axis list; an empty list reduces nothing. Every reduction, including `argmin`, `argmax`, `var` and `std`, accepts a `ReduceOptions` object whose `keepdims: true` keeps reduced axes with length 1. The option follows the axis argument, and for `var` and `std` it follows `ddof`. `ReduceShape<S, A, K>` infers the result shape for literal nonnegative axes and a literal `keepdims`; negative or non-literal axes and a non-literal `keepdims` produce a dynamic shape. Repeated axes fail with `NMATH_INDEX_INVALID`, including a negative and a positive form of the same axis, and out-of-range axes fail with `NMATH_INDEX_OUT_OF_BOUNDS`. A non-boolean `keepdims` fails with `NMATH_INDEX_INVALID`. `argmin` and `argmax` select at most one axis, as in NumPy. Axis lists for `var`, `std` and the scans remain targets. `keepdims` reshapes the native reduction result, so it adds no extra computation.

Index reductions return the first equal value's position, keep the first NaN position, and compare complex values lexicographically. They accept one axis or no axis. A zero-length reduced axis fails with `NMATH_SHAPE_MISMATCH`; with a nonempty reduced axis and an empty retained shape the result is empty. Product reductions use the multiplicative identity for zero-length reduced axes. GPU requests reject product and index reductions before admission with `NMATH_GPU_UNSUPPORTED_OPERATION`.

The NumPy `equal`, `not_equal`, `less`, `less_equal`, `greater` and `greater_equal` functions return `Expr<"bool", ...>` with compile-time broadcast shape inference. Two-array calls reject incompatible static shapes and `str`/temporal operands in the declarations. Ordering functions accept only non-complex numeric dtypes; `equal` and `not_equal` also accept complex dtypes. Weak `number`, `bigint`, `boolean` and `Complex` scalars are supported, with complex scalars excluded from ordering. Runtime validation returns `NMATH_DTYPE_UNSUPPORTED` for rejected dtype combinations and `NMATH_SHAPE_BROADCAST` for invalid shapes. GPU execution rejects the bool result before admission.

The core and NumPy entry points export `where(condition, x, y)`. The condition must be an NMath value with a numeric or bool dtype. Each branch is an NMath value or a weak `number`, `bigint`, `boolean` or `Complex` scalar. The declarations return `Promote` of two array branches, `PromoteWeak` for one weak branch, and `Promote` of the weak default dtypes for two weak branches. The result shape is the static broadcast of all three operands, and incompatible static shapes or `str`/temporal operands are rejected in the declarations. A JS `number` is a weak float, so an integer branch with a `number` becomes `float64`; use a `bigint` to keep the integer dtype. Runtime validation returns `NMATH_DTYPE_UNSUPPORTED`, `NMATH_SHAPE_BROADCAST` or `NMATH_CONTEXT_MISMATCH`. GPU execution rejects `where` before admission. The one-argument form remains a target.

The NumPy entry point exports the math ufuncs `sqrt`, `cbrt`, `exp`, `exp2`, `expm1`, `log`, `log2`, `log10`, `log1p`, `sin`, `cos`, `tan`, `arcsin`, `arccos`, `arctan`, `sinh`, `cosh`, `tanh`, `arcsinh`, `arccosh`, `arctanh`, `deg2rad`, `rad2deg`, `fabs`, `rint`, `spacing`, `absolute`, `square`, `reciprocal`, `sign`, `floor`, `ceil`, `trunc`, `conjugate`, `isnan`, `isinf`, `isfinite`, `signbit` and `logical_not`, and the NumPy 2 aliases `abs`, `conj`, `asin`, `acos`, `atan`, `asinh`, `acosh` and `atanh`. Each takes one NMath value and keeps its static shape. `MathFloatDType` maps real input dtypes to the float loop dtype. The declarations reject complex inputs except for `conjugate` and the `isnan`, `isinf`, `isfinite` and `logical_not` predicates, bool `sign`, non-float `reciprocal`, and `str`/temporal inputs; runtime validation rejects the same combinations with `NMATH_DTYPE_UNSUPPORTED`. `out`, `where`, `casting` and `dtype` ufunc arguments and ufunc methods remain targets.

The NumPy entry point also exports `bitwise_and`, `bitwise_or`, `bitwise_xor`, `left_shift`, `right_shift`, `logical_and`, `logical_or`, `logical_xor` and `invert`, with the NumPy 2 aliases `bitwise_not`, `bitwise_invert`, `bitwise_left_shift` and `bitwise_right_shift`. Bitwise declarations accept bool and integer arrays and `bigint` or `boolean` scalars. A JS `number` is a weak float, so the declarations and runtime reject it for bitwise and shift operators. A `BitwiseCheck` argument constraint rejects operand pairs without a common integer dtype, such as int64 with uint64. Logical declarations accept any numeric operands and weak `number`, `bigint`, `boolean` and `Complex` scalars and return `Expr<"bool", ...>`.

The NumPy entry point exports the binary math functions `maximum`, `minimum`, `fmax`, `fmin`, `fmod`, `floor_divide`, `copysign`, `nextafter`, `arctan2` (alias `atan2`), `hypot`, `heaviside`, `logaddexp` and `logaddexp2`. Extremum declarations return `Promote` of two arrays or `PromoteWeak` with a weak scalar and accept complex dtypes. `fmod` and `floor_divide` accept real dtypes and map bool results to int8. Float-valued declarations return `Promote<MathFloatDType<A>, MathFloatDType<B>>` for two arrays and the float loop of the NEP 50 weak promotion otherwise. Complex operands are rejected outside the extremum functions.

Reads accept `newaxis` (JS `null`, exported as `newaxis`) and the exported `ellipsis` sentinel in addition to integer, slice, `indices` and `mask` selectors. The package layer expands one ellipsis into full slices, applies the native selectors, and then transposes and reshapes the result to insert length-1 axes. Integer and array selectors form one advanced block when an array selector is present; a `newaxis` between them breaks adjacency and moves the block to the front, as in NumPy. More than one ellipsis fails with `NMATH_INDEX_INVALID`. Writes accept `ellipsis` but reject `newaxis` with `NMATH_INDEX_INVALID`, because NumPy's value-shape handling for new axes in assignments is not implemented. `IndexShape` inserts literal 1s for `newaxis` in basic reads; an ellipsis, `newaxis` combined with an array selector, or several array selectors produce a dynamic shape. `.nts` bracket reads and writes use the same selectors through the compiler runtime.

The NumPy `var` and `std` wrappers preserve the runtime result dtype: float16 stays float16, float32 and complex64 become float32, and other dtypes become float64. They accept one axis or no axis and a finite `ddof` that defaults to zero. Integer and boolean declarations therefore return `float64`. String and temporal operands are rejected by the declarations and again at runtime with `NMATH_DTYPE_UNSUPPORTED`.

The NumPy `cumsum` and `cumprod` wrappers return the sum-promoted dtype. Without an axis the result type is a one-dimensional dynamic shape, because the flattened length is not part of the tuple type. A literal or dynamic axis keeps the input shape. The declarations reject string and temporal operands, and runtime validation rejects them again with `NMATH_DTYPE_UNSUPPORTED`. GPU requests reject scans before admission with `NMATH_GPU_UNSUPPORTED_OPERATION`.

The NumPy entry point exports `squeeze(a, axis?)`, `expand_dims(a, axis)`, `swapaxes(a, axis1, axis2)`, `moveaxis(a, source, destination)`, `ravel(a, order?)`, `flip(a, axis?)`, `fliplr(m)` and `flipud(m)`. They compose the existing lazy layout nodes in NumPy 2.5.4's order and keep the dtype, context, view and snapshot behavior of those nodes: `squeeze` and `expand_dims` use the C-order reshape, `ravel` uses the native C-order flatten that views a C-contiguous input and copies any other layout, `swapaxes` and `moveaxis` use transpose, and the flips use negative-step slice reads. Axes accept one integer or an integer list and may be negative; `expand_dims` normalizes them against the output rank, and `moveaxis` inserts each source axis at its destination in ascending destination order. Axis validation runs when the expression is built: an out-of-range axis fails with `NMATH_INDEX_OUT_OF_BOUNDS`, and a non-integer axis, a repeated axis or `moveaxis` lists of different lengths fail with `NMATH_INDEX_INVALID`. Squeezing an axis whose length is not 1, `fliplr` below two dimensions and `flipud` on a zero-dimensional input fail with `NMATH_SHAPE_MISMATCH`. Like NumPy, `squeeze` accepts the integer axis 0 or -1 for a zero-dimensional input. `ravel` supports C order only and rejects other orders with `TypeError`. Declarations always keep the dtype. For tuple shapes and literal integer axes they infer the exact result shape, including negative axes, and reject out-of-range, repeated or non-integer axes, a literal non-1 squeeze length, mismatched `moveaxis` lengths and too few dimensions for `fliplr` and `flipud`. Non-literal axes keep the rank where it is known, `squeeze` without an axis needs literal dimensions for a static shape, `ravel` returns `[number]`, and unknown-rank inputs return `number[]`. A union axis type yields the union of the shapes of its alternatives. GPU requests reject before admission, as for the underlying layout nodes. The tests compare 94 NumPy 2.5.4 cases, including empty and zero-dimensional inputs and error classes, for exact shape and C-order values.

The NumPy entry point exports `linspace(context, start, stop, num?, {endpoint?, dtype?, retstep?})`, `logspace(context, start, stop, num?, {endpoint?, base?, dtype?})`, `eye(context, N, M?, {k?, dtype?})`, `identity(context, n, dtype?)`, `empty(context, shape, dtype)` and `zeros_like`, `ones_like`, `full_like` and `empty_like`, each taking the source value first and an optional result dtype. Range and identity constructors take an explicit context, default to `num` 50, `endpoint` true, `base` 10 and `float64`, and accept bool, integer, floating and complex dtypes for scalar JS-number endpoints. `linspace` reproduces NumPy 2.5.4's float64 order exactly: `div` is `num - 1` with an endpoint and `num` without one; a nonzero `step = (stop - start) / div` multiplies each index, a zero step divides each index by `div` before multiplying by the delta, and `div <= 0` gives a NaN step and multiplies by the delta; `start` is added, and the last sample becomes `stop` when the endpoint is included and `num > 1`. Floating and complex dtypes round the float64 samples once; integer dtypes floor first; bool maps every nonzero value, including NaN, to true. `retstep: true` returns a frozen `[samples, step]` tuple with a float64 step. `logspace` raises `base` to the float64 `linspace` samples with JS `Math.pow` and casts once, truncating toward zero for integer dtypes. Like C `pow`, a base of 1 gives 1 for every exponent, including NaN, and a base of -1 gives 1 for infinite exponents, where `Math.pow` returns NaN. `Math.pow` can otherwise differ from the platform C `pow` by an ULP, so the reference fixture accepts 4 ULP for float64 and 1 ULP for float32, and requires exact integer results for its recorded inputs. `eye` sets row `r`, column `r + k` to one where that column exists and accepts any safe-integer `k`. Integer casts outside the target range, including NaN and infinities, fail with `RangeError` because NumPy's result is platform-dependent. Counts and dimensions follow the context dimension rule and fail with `NMATH_SHAPE_MISMATCH`; non-number endpoints or bases, non-boolean flags, non-integer `k` and unknown options, including `axis`, `device` and `order`, fail with `TypeError`; other dtypes fail with `NMATH_DTYPE_UNSUPPORTED`. The `_like` functions create a new array in the source value's context with its shape, and keep its string width or time unit when the result dtype is unchanged. `ones_like` uses `"1"` for strings and one tick for temporal values; `full_like` rejects strings longer than the source width instead of truncating and requires the source time unit. A value without a context fails with `NMATH_CONTEXT_MISMATCH`. `empty` and `empty_like` zero-fill, while NumPy leaves the contents unspecified. Every constructor checks the CPU budget before it builds input buffers and fails with `NMATH_MEMORY_BUDGET_EXCEEDED`. Declarations keep literal `num`, `N` and `M` values in `[N]` and `[N, M]` result shapes and use `number` for dynamic sizes; `retstep: true` selects the tuple overload. `_like` results keep the source's static shape and dtype unless a dtype is given, and `full_like` requires a scalar of the result dtype. String and temporal dtypes are rejected in the range and identity declarations. Array-valued endpoints and bases, `axis`, `device`, `like`, `order`, `subok` and the `_like` `shape` override remain targets.

The NumPy entry point exports `dot`, `vdot`, `inner`, `outer`, `diagonal`, `trace`, `clip` and `diff`. They compose existing lazy nodes in the package layer and add no native node. `dot(a, b)` multiplies when an operand is 0-d; otherwise it contracts the last axis of `a` with the second-to-last axis of `b`, or with its only axis when `b` is one-dimensional, and returns shape `a.shape[:-1] + b.shape[:-2] + b.shape[-1:]` through `matmul`, `transpose` and `reshape`. `inner` contracts the last axes without conjugation and returns `a.shape[:-1] + b.shape[:-1]`. `dot` and `inner` flatten the non-contracted axes into one matmul, except when a flattened dimension would exceed the per-dimension limit, as empty results can; they then use a broadcast batched matmul that keeps every dimension. `vdot` flattens both operands, conjugates a complex first operand and returns a 0-d result; `outer` flattens both operands to shape `(M, N)`. Mismatched contraction lengths and `vdot` sizes fail with `NMATH_SHAPE_MISMATCH`, as `matmul` does. The products keep NumPy's result dtype, so bool stays bool and integers do not widen. `diagonal(a, offset, axis1, axis2)` moves the two axes to the end and selects them with two broadcast index arrays, so the diagonal is the last axis; offsets beyond the matrix give an empty last axis. `trace` sums that axis with the sum node's promotion. Fewer than two dimensions or equal axes fail with `NMATH_SHAPE_MISMATCH`, out-of-range axes with `NMATH_INDEX_OUT_OF_BOUNDS` and a non-integer offset with `NMATH_INDEX_INVALID`. `clip(a, a_min, a_max)` follows NumPy 2.5.4 `_clip`: `null` or `undefined` means no bound; with both bounds, the array, array bounds and weak scalar bounds first resolve one dtype as the three-input `um.clip` does, so a float bound widens an integer array before an integer bound is checked; the bounds apply as `minimum(maximum(a, a_min), a_max)` so NaN propagates and `a_min > a_max` yields `a_max`, and a `bigint` bound at or beyond an integer dtype's limit is dropped. Without bounds the result is `positive(a)`, which rejects bool input with `NMATH_DTYPE_UNSUPPORTED` as NumPy raises. Weak `bigint` and `boolean` bounds keep the array dtype; a JS `number` is a Python float and makes integer input float64. `diff(a, n, axis)` subtracts repeated slices, uses `not_equal` for bool and turns datetimes into timedeltas; `n = 0` returns a view of the input, a negative or non-integer `n` fails with `NMATH_INDEX_INVALID` where NumPy raises `ValueError`, and 0-d input fails with `NMATH_SHAPE_MISMATCH`. The fourth argument `{ prepend, append }` joins values before and after `a` along the axis with `concatenate` before differencing, as NumPy does; a 0-d NMath value repeats across the other axes through zero-index reads, and JS scalars become strong arrays in the context of `a` when the expression is built: `number` as float64, `bigint` as int64, `boolean` as bool and `Complex` as complex128, matching NumPy's `asanyarray` of Python scalars. The declarations compute the edge dtype as the `concatenate` dtype of the present edges and `a`, keep the dtype of `a` as one alternative for an optional edge that can be `undefined`, and reject edges that cannot join, and unknown options fail with `NMATH_INDEX_INVALID`. The declarations reject string and temporal operands for the products and `clip`, strings for `trace` and `diff`, and fewer than two literal dimensions for `diagonal` and `trace`. They keep the promoted dtype and give literal shapes for `dot` and `inner` of literal tuples, one-dimensional `outer` and default-axis `diagonal` and `trace`; other shapes are dynamic. The fixed NumPy 2.5.4 oracle uses exact small values for bool, integer, float16, float32, float64, complex64 and complex128 inputs. Its criterion is exact equality with NaN equivalence, except that signed zeros are not compared because NumPy's 0-d `dot` and `inner` path can return `+0` where IEEE multiplication returns `-0`.

The NumPy `any(a, axis?, { keepdims })`, `all` and `count_nonzero` wrappers compose a truthiness comparison with the lazy sum reduction: `any` compares the int64 count of truthy elements with zero, `all` compares the count of falsy elements with zero, and `count_nonzero` returns the int64 count (NumPy `intp`). Truthiness follows NumPy: nonzero values and NaN are true, and a complex value is true when either component is nonzero. Empty reductions give `false` for `any`, `true` for `all` and `0n` for `count_nonzero`. The axis may be undefined, one axis or an axis list, and the result shape uses `ReduceShape`; `any` and `all` return `bool`. `isclose(a, b, { rtol, atol, equal_nan })` follows NumPy 2.5.4 `numeric.py`: `b` becomes inexact first (integer and bool references become float64, JS bigint and boolean scalars become numbers), and the result is `abs(a - b) <= atol + rtol * abs(b)` where `b` is finite, or `a == b`, with `isnan(a) & isnan(b)` added under `equal_nan`. Defaults are `rtol` 1e-05 and `atol` 1e-08; tolerances are JS numbers, not arrays. Either operand may be a weak JS scalar, and the result has the broadcast shape. Complex magnitudes use the native vector infinity norm over an appended length-1 axis, because the `absolute` node has no complex loop yet. `allclose` is `all(isclose(...))`. `array_equal(a1, a2, { equal_nan })` and `array_equiv(a1, a2)` return `Expr<"bool", []>`; shapes are known before execution, so different shapes, or shapes that do not broadcast for `array_equiv`, give a rank-0 constant that computes to `false` without reading the inputs. Rank-0 results compute to JS `boolean` or `bigint` values. The declarations and runtime checks reject string and temporal operands, unknown options fail with `NMATH_INDEX_INVALID`, and GPU admission rejects the bool comparisons. The fixed NumPy oracle requires exact bool and count results.

The NumPy `concatenate(arrays, axis = 0)`, `stack`, `vstack`, `hstack`, `dstack`, `column_stack` and `append` functions use the native concatenate node. Operands must be NMath arrays or expressions; other values fail with `TypeError`. `axis: null` flattens every operand in C order before joining, and `append` without an axis does the same for its two operands. `stack` checks that every shape is equal, reshapes each operand with a length-1 axis at the normalized output axis and joins along it; an empty list or different shapes fail with `NMATH_SHAPE_MISMATCH`. `vstack`, `hstack` and `dstack` follow NumPy 2.5.4 `shape_base`: they apply `atleast_2d`, `atleast_1d` or `atleast_3d` and join along axis 0, along axis 0 or 1 depending on whether the first operand is 1-D, or along axis 2. `column_stack` reshapes 0-d and 1-D operands to columns and joins along axis 1. `atleast_1d`, `atleast_2d` and `atleast_3d` return reshape views; one operand returns one expression, and zero or several return a frozen tuple, as NumPy returns a tuple. The result context is the first operand context. The declarations accept any NMath value through the `NMathValue` brand, compute the result dtype like NumPy's multi-operand `result_type`, promoting every operand with the operand dtype of the highest NumPy legacy type number and combining the results, with temporal operands joining only their own dtype, and reject dtypes that cannot join, statically out-of-range axes and 0-d `concatenate` operands. With literal tuple shapes and axes they keep every dimension except the joined one, which is dynamic; `stack` inserts the operand count of a literal tuple, and a union axis gives the union of each alternative's shape. The `out`, `dtype` and `casting` arguments remain targets. The fixed NumPy 2.5.4 oracle requires exact shapes, dtypes, string widths, time units and values.

`split`, `array_split`, `hsplit`, `vsplit` and `dsplit` follow NumPy 2.5.4 `_shape_base_impl`: a section count gives parts whose lengths differ by at most one with the longer parts first, and an index list gives the division points `[0, ...indexes, length]` that slice with Python rules. Each part is a basic slice view, and the result is a frozen array. `split` and the `h`/`v`/`d` forms fail with `NMATH_SHAPE_MISMATCH` when a count does not divide the axis, and the directional forms fail with `NMATH_SHAPE_MISMATCH` below their minimum rank. `repeat(a, repeats, axis = null)` flattens without an axis or a 0-d input, so a 0-d input accepts axis 0 or -1, and selects each position by its count with one integer-array read, so the result is a copy; a count list must have one entry or one per position (`NMATH_SHAPE_BROADCAST`). `tile(A, reps)` pads the shorter of the input shape and `reps` with leading ones, copies the input with a reshape and then reads each repeated axis with a modular integer-array index. `roll(a, shift, axis = null)` broadcasts shifts against axes, where an empty list broadcasts to no pairs, adds the shifts of a repeated axis, takes Python's non-negative modulo per axis and joins the two slices of each rolled axis with the concatenate node; without an axis it rolls the flattened input and restores the shape, and with no effective shift it still returns a copy. `repeat` and `tile` check the int64 size of each expanded index list against the CPU budget before building it and fail with `NMATH_MEMORY_BUDGET_EXCEEDED` when it does not fit. Negative or non-integer counts, sections, repetitions and shifts fail with `NMATH_INDEX_INVALID`. The declarations keep literal dimensions except the split, repeated or tiled axes and reject statically out-of-range axes and too few literal dimensions. The fixed NumPy 2.5.4 oracle requires exact shapes, dtypes and values.

## Numeric tables

The pandas and Polars numeric table entry points use the same native table executor. A completed result is returned by a Promise; no batch iterator or AsyncIterable is exposed. Table work supports CPU only and rejects explicit GPU selection. Row-local arithmetic, casts, selection and filtering can execute in bounded internal batches. Snapshots and completed results still require their full memory budget; sort, joins, groups and non-row-local expressions retain materialization boundaries. This bounded subset does not establish full Polars streaming compatibility.

Pandas `DataFrame.pivot(index, columns, values)` requires unique row/column pairs and rejects duplicates with `NMATH_INDEX_INVALID`. `pivotTable(index, columns, values, { aggfunc })` defaults to `mean` and accepts `sum`, `mean`, `min`, `max` or `count`. Both are asynchronous and return a new `DataFrame`. The row key stays a regular column, and generated value columns use the string form of each column key; this is a JS adaptation of pandas' index-based result. Polars `DataFrame.pivot(on, index, values, aggregate?)` and `LazyFrame.pivot` default to unique pairs and accept the same aggregate names. `collect()` materializes the result. Both adapters exclude invalid keys, keep Pandas axes sorted and preserve Polars first-appearance order, and mark generated value columns nullable. Keys and values outside numeric/boolean tables fail with `NMATH_DTYPE_UNSUPPORTED`. Multiple keys, pivot on string/temporal columns and full upstream pivot options remain targets.

A pandas Series accepts optional `index` labels and `validity` column arguments after its values and name. Labels are strings or numbers. `loc(label)` selects matching labels; `iloc` preserves selected labels. Integer `iloc` on a nullable Series is rejected because the current scalar expression cannot carry a validity mask. Arithmetic aligns Series with the same unique label set; identical duplicate-label sequences also work. Unmatched or differently ordered duplicate labels require explicit alignment and are rejected. Full outer label alignment remains a target. Nullable Series arithmetic and reductions are rejected rather than silently discarding nulls.

A pandas DataFrame accepts `{index, validity}` as optional constructor metadata. Columns supplied as Series must already have matching label sequences. `filter(booleanColumn)` and `sortValues(column, options)` return completed frames and preserve labels. `merge(other, key, options)` supports inner and left joins and matches null keys. `groupBy(key, value, operation, options)` returns a two-column result with the group key as a column, equivalent to the supported `as_index=False` workflow. It defaults to sorted keys and dropped null keys; `sort:false` and `dropna:false` are supported.

For pandas grouping, the default `dropna:true` also drops float32 and float64 NaN keys, even when the validity mask marks them valid. `dropna:false` retains NaN and invalid-mask groups. The result keeps the group key dtype.

Polars Series accept an optional validity column. LazyFrame supports named `select`, `filter`, `sort`, `join` and `groupBy`, followed by `collect`. Polars has positional rows, retains null groups and defaults to unmatched null join keys. `nullsEqual:true` enables null-key matching. Group results retain first-seen key order. Arithmetic projections are available before row operations on non-nullable columns. Computed projections after row operations or on nullable inputs remain targets and fail explicitly. Named selection on nullable inputs is supported.

Joins use a single key and `how:'inner'|'left'`. `rightKey` chooses a differently named right key. An equal-name join key is coalesced to the left key by removing only the right key column. Other overlapping right names receive `suffix`, defaulting to `_right`; collisions among retained output names fail with a stable error. This suffix option is an explicit JS adaptation, not the full pandas suffix API. Group aggregate dtype selection differs between entry points: pandas retains narrow integer sums when they fit and widens on overflow; Polars widens 8/16-bit sums to int64 and returns uint32 counts. Polars float32 mean remains float32, while pandas mean is float64.

`Series.toPolars`, `DataFrame.toPolars`, `Series.toPandas` and `DataFrame.toPandas` preserve names, numeric dtypes and validity expressions. These synchronous conversions wrap the same lazy column handles; they do not copy buffers or move data between contexts. Calling compute/collect makes a native execution snapshot and returns independent result storage. pandas-to-Polars conversion rejects a non-default index unless `dropIndex:true` explicitly authorizes label loss. pandas `Series.toColumn()` returns the name, values, validity and labels together. `toArray()` explicitly drops the name and rejects nullable Series; use `toColumn()` to preserve the mask. Cross-context copies remain explicit array operations and require copying both values and validity columns.

Errors use the existing stable codes and English recovery guidance. Table schema errors do not include input values or column names. Names are resolved to positions before native execution.

### NPZ API

`ctx.saveNpz(path, arrays, options?)` writes a `ReadonlyMap<string, NMathArray<any, any>>` in insertion order. Arrays may have different dtypes and shapes, but must belong to `ctx`. Options are `{ compressed?: boolean, overwrite?: boolean, signal?: AbortSignal }`. `compressed` and `overwrite` default to `false`. The core method uses the exact path without adding a suffix and returns `Promise<void>`.

`ctx.loadNpz(path, { signal }?)` returns `Promise<Map<string, NMathArray<ComputableDType, number[]>>>`. Member names remain Map keys, including names such as `__proto__`; they are never assigned as object properties. Rank-zero members remain arrays and expose their scalar through `item()`. Callers dispose each returned array when finished. Empty archives return an empty Map.

The NumPy entry point exports these explicit JS adaptations:

```ts
interface NpzInputs {
  positional?: readonly NMathArray<any, any>[];
  named?: ReadonlyMap<string, NMathArray<any, any>>;
}

savez(context, path, inputs?: NpzInputs, options?: { overwrite?: boolean; signal?: AbortSignal }): Promise<void>;
savez_compressed(context, path, inputs?: NpzInputs, options?: { overwrite?: boolean; signal?: AbortSignal }): Promise<void>;
loadNpz(context, path, options?: { signal?: AbortSignal }): Promise<Map<string, NMathArray<ComputableDType, number[]>>>;
```

`savez` uses stored members; `savez_compressed` uses DEFLATE. Both append `.npz` when the path does not already end with that exact suffix. They insert named entries in Map order, followed by positional entries named `arr_0`, `arr_1`, and so on. A positional name that collides with a named entry rejects with `TypeError` before native submission. Omitted inputs produce an empty archive. There is no pickle option. Existing `load` remains NPY-only; NPZ uses the explicit `loadNpz` method.

All NPZ operations use native scheduled file jobs and explicit contexts. One save freezes all input arrays at a consistent execution-start snapshot boundary, including arrays that share storage. Snapshot offsets and copied payloads count against the context CPU memory budget; a save fails before publication if a required reservation does not fit. Pre-publication cancellation or failure preserves existing output, and writes reject existing destinations unless `overwrite: true`. Successful atomic publication is terminal success even if the signal aborts before Promise completion. Reads retain cancellation checks through scheduler completion. Name, compression, size, dtype and layout limits follow the runtime NPZ contract and remain visible compatibility constraints.

## Random generator API

`context.generator(seed)` and `numpy.random.defaultRng(context, seed)` return the same lazy PCG64 generator. The explicit seed is a nonnegative integer of at most 128 bits. Use bigint for seeds outside the safe JS integer range.

Methods use an explicit shape, with `[]` for a scalar:

- `random(shape, dtype = "float64")`, with float32 or float64.
- `integers(low, high, shape, { dtype = "int64", endpoint = false } = {})`, with bool or signed/unsigned 8/16/32/64-bit dtypes. Passing `undefined` for high uses `[0, low)`. Bounds are safe JS integers or bigint; endpoint includes the upper bound. Full-width uint64 exclusive high accepts `2n ** 64n`.
- `uniform(low, high, shape)`, returning float64.
- `standard_normal(shape, dtype = "float64")`, with float32 or float64.
- `normal(loc, scale, shape)` and `exponential(scale, shape)`, returning float64.

For these three methods with a configurable dtype, a definitely present dtype keeps its exact result type. An optional dtype argument or `integers` option includes the documented default in its result dtype when the value can be `undefined`. Omitted dtypes retain the exact default type. The declared computed storage follows every possible result dtype.

Distribution parameters are scalars. Each `compute()` is a new scheduled native job. Jobs sharing a generator run in request order and commit state only on success. Invalid bounds, allocation errors and cancellation before completion preserve generator state, including cached uint32 values. No JS random kernel or Python runtime is used.

Parameter broadcasting, `out`, other distributions and bit generators, optional entropy seeding, state import/export and SeedSequence spawning remain targets. Integer float coercion is not supported: callers must supply safe integers or bigint explicitly. These methods do not establish full NumPy random compatibility or cross-platform numerical acceptance.

### CSV and JSON JS adaptations

`ctx.readText(path, 'csv' | 'json', {schema?, signal?}?)` returns a Promise of `{columns, validity}` Maps. `schema` is a complete ordered `ReadonlyMap<string, TextDType>`; `TextDType` includes the current real numeric and boolean dtypes. Every returned column has a bool validity array. Dispose both values and masks. `ctx.writeText(path, format, columns, validity?, {overwrite?, signal?}?)` returns `Promise<void>` and accepts numeric lazy columns owned by the context. Paths are used exactly as supplied. Overwrite defaults to false. Both methods use one native scheduled CPU file job.

The pandas and Polars entry points export `read_csv(context, path, options?)` and `read_json(context, path, options?)` returning their respective DataFrame in a Promise. pandas frames expose `toCsv(context, path, options?)` and `toJson`; Polars frames expose `writeCsv` and `writeJson`. These names, explicit contexts, Maps, AbortSignals and Promise results are JS adaptations. JSON uses records orientation for both entry points; it does not implement pandas' default columns orientation. CSV writes a header without an index. Non-default pandas indexes require `dropIndex:true` to authorize loss; reads create a default positional index. Use an explicit schema to preserve narrow/all-null dtypes and empty JSON column schemas. Exact int64/uint64 values return as bigint arrays.

The numeric token, validity, memory, cancellation, atomic publication and unsupported-option limits are defined in the runtime text-file contract. Unsupported orientations/options, richer dtypes and upstream default-policy differences remain open compatibility obligations. No Python runtime is required.

## Workflow benchmark protocol

The development-only harness in `packages/nmath/scripts/benchmarks/` runs three synthetic workflows: a 128 by 128 float32 matrix product, a 32,768-row int64 group sum with 64 groups through both pandas and Polars APIs, and an 8,192-element float32 Horner polynomial authored in `.nts`. The seed is 20261029. Each stream starts from that seed and uses the unsigned 32-bit recurrence `state = 1664525 * state + 1013904223`; values are `(state >>> 24) % 16 - 8`. The matrix right operand is the transpose of the left. Table keys are row index modulo 64. The algorithm is `(x * 2 + 3) * x + 1`.

Small integer-valued inputs keep every float32 intermediate exact. Full-output SHA-256 digests cover comma-separated decimal integer values, with schema and missing-value checks performed separately. Exact equality is a workload-specific criterion, not a tolerance decision for general floating-point operations. An independent integer reference checks generated oracle results. The checked-in fixture records NumPy 2.5.4, pandas 3.1.0 and Polars 2.1.0; regeneration rejects other versions. No Python dependency is needed for native benchmark execution or its correctness checks.

Run with Node.js 24 and the pinned pnpm from the repository root:

```sh

pnpm exec turbo run benchmark --filter=@delinoio/nmath -- --device gpu --output /tmp/nmath-gpu.json
pnpm exec turbo run test:benchmarks --filter=@delinoio/nmath
```

The output parent directory must exist. Each run replaces the requested report with atomic complete JSON snapshots. Use a separate output path for each experiment. Windows forced termination does not provide this guarantee; its SIGTERM test is skipped. Errors produce a failed report and a nonzero exit. SIGKILL or a power loss cannot produce a final status; a running report is incomplete evidence.

`benchmark` and `test:benchmarks` depend on the package and compiler builds and are uncached. `benchmark:originals` is uncached and development-only. Put a dedicated environment containing the exact versions in `compatibility/oracle-requirements.txt` on PATH before running it:

To regenerate the fixture, append `--fixture test/fixtures/benchmarks/originals.json`; that path is relative to the owning package. Turbo passes the five listed thread controls explicitly. The report records their values and NumPy build configuration. Missing original environments or mismatched versions fail rather than substitute other releases. Python RSS high-water measurement is unavailable on platforms without the `resource` module and is reported as null.

Default runs use two warmups and nine measured executions, configurable with `--warmup` and `--samples`. Each native workload checks all output values, shape, dtype and validity before timing, and checks every measured result outside the timed interval. The harness reports raw samples, median, nearest-rank p95, median absolute deviation and extrema without deleting outliers. Run performance experiments separately from test suites and other workloads; repeat independent process runs when studying variance. These small representative inputs do not establish scaling behavior for all dataset sizes.

Native reports separate import, compilation, setup/input construction, first execution, compute wall time and output extraction. Native execution metrics include snapshots and scheduler work within their existing boundary. Wall minus queue and execution metrics is a signed residual estimate, not an isolated N-API timer. A one-element probe exposes a small dispatch workload. RSS samples, process-lifetime maximum RSS and cumulative context CPU/GPU allocation peaks have different accounting scopes; none is advertised as a kernel-only memory measurement. Original benchmarks exclude imports, input generation, correctness checks and output extraction from timed compute, and expose first execution separately.

GPU requests apply only to numerical arrays. Tabular measurements remain CPU. A full-array identity probe reports transfer-inclusive time and logical input/output bytes. Isolated upload/download times are null because public metrics provide no transfer timestamps; that measurement gap remains explicit. Device initialization and pipeline setup may occur in first execution. No automatic fallback, retry, official GPU allowlist approval or speedup claim follows from a completed report. Known unaccepted GPU power differences remain outside this workload and are not waived.

Reports record source revision, dirty-tree state, script/fixture/algorithm/native-binary hashes, exact software and hardware metadata, commands, versions and seed. Original-library reports obtain Linux CPU models from `/proc/cpuinfo` and macOS models from `sysctl`. They record identification status and source; an unavailable model is null with an explicit reason, never an architecture substituted as a model. Keep local reports and logs in external validation artifacts, not source-of-truth contracts. Cross-platform execution and wider numerical acceptance remain separate release requirements.

### Columnar file API

`ctx.readColumnar(path, 'arrow' | 'parquet', {signal}?)` returns a Promise of `{columns, validity, rows}`. Columns are context-owned materialized `NMathArray` instances keyed by name; validity masks are materialized boolean arrays. Their public types expose scalar reads, TypedArray conversion and disposal. `ctx.writeColumnar(path, format, columns, validity?, {overwrite, signal}?)` returns `Promise<void>`. The exact local path is used; suffixes are not added. `overwrite` defaults to false. Dispose returned value and validity arrays when finished.

pandas exports `read_parquet(context, path, options?)` and `read_feather(context, path, options?)`, each returning `Promise<DataFrame>`. DataFrame methods `to_parquet(context, path, options?)` and `to_feather(context, path, options?)` return `Promise<void>` and reject non-default index labels before submission. This explicit-context argument is a JS adaptation. The default index is reconstructed on read. The file adapter preserves numeric dtype and null masks instead of applying pandas' default nullable-integer-to-float inference; compare this representation with pandas `dtype_backend="numpy_nullable"`. Unsupported pandas metadata files fail explicitly.

Polars exports `read_parquet(context, path, options?)` and `read_ipc(context, path, options?)`; DataFrame methods are `write_parquet(context, path, options?)` and `write_ipc(context, path, options?)`. They preserve supported column names, dtypes, nullability and positional rows. File options currently contain only `signal` and, for writes, `overwrite`. Engine, compression, column projection and original-library options not listed here remain targets rather than silently ignored options. All file adapters use scheduled native CPU work and completed Promise results. Format, codec, metadata and dtype limits follow the runtime contract.

DataFrame columnar read adapters reject nonempty zero-column tables with `NMATH_DTYPE_UNSUPPORTED` because their constructors cannot preserve an explicit row count. `ctx.readColumnar` retains that row count for direct callers.

### Matrix product adaptation

`numpy.matmul(a, b)` and `a.matmul(b)` take two numeric or boolean lazy operands and return the same native expression. They infer the promoted dtype and broadcast leading batch dimensions. A vector on the left removes its temporary row axis; a vector on the right removes its temporary column axis. Two vectors produce a rank-zero expression. Known invalid core or batch dimensions and scalar/string/temporal operands are rejected by declarations; runtime inference validates dynamic dimensions with the same rules. Unknown batch dimensions preserve other known axes. File/order/output/ufunc options remain separate compatibility targets.

Matrix products use native worker execution, actual-start snapshots, context ownership, cancellation and budget admission. Strided operands are frozen in logical order at execution start. Results are independent allocated values. Exact small-value NumPy fixtures cover shape, dtype, vector promotion, empty axes and all current numeric/boolean dtypes without setting a tolerance for arbitrary floating-point products. The runtime contract owns kernel and GPU restrictions.

### Linear algebra and FFT adaptation

The NumPy entry point exports `linalg.solve(a, b)`, `linalg.inv(a)`, `linalg.det(a)` and `fft.fft(a, options)`, `fft.ifft`, `fft.rfft`, `fft.irfft`. Arguments are contextual lazy arrays or expressions; results are lazy expressions and use normal `compute()` and complex transport. FFT options are `{n?, axis?, norm?: "backward" | "forward" | "ortho"}`. Unknown options, including `out`, fail explicitly. The native runtime contract owns batch, dtype, normalization and resource behavior. Singular linear systems use `NMATH_LINALG_SINGULAR`.

`fft.rfft2`, `fft.irfft2`, `fft.rfftn`, `fft.irfftn`, `fft.hfft` and `fft.ihfft` compose the one-axis lazy transforms exactly as NumPy 2.5.4 does: `rfftn` applies `rfft` to the last selected axis and then `fft` to the remaining axes in reverse order; `irfftn` applies `ifft` forward and `irfft` last, with the last length defaulting to `2 * (m - 1)`; `s` without `axes` selects the last `len(s)` axes. `hfft` conjugates its input and runs `irfft` with the swapped normalization direction; `ihfft` conjugates the `rfft` result with the swapped direction. `rfft2`, `rfftn` and `ihfft` reject complex inputs in their declarations and at runtime, like `rfft`. Shapes are dynamic in the declarations. The tests apply NumPy's `test_pocketfft` relations at `atol` 1e-6; forward-output criteria remain pending as for the other transforms.

`linalg.cholesky(a, { upper })`, `linalg.qr(a, mode)`, `linalg.eigh(a, UPLO)`, `linalg.eigvalsh(a, UPLO)`, `linalg.svd(a, { full_matrices, compute_uv, hermitian })`, `linalg.svdvals(a)` and `linalg.slogdet(a)` follow NumPy defaults: lower Cholesky, `mode: "reduced"`, `UPLO: "L"` and `full_matrices: true`. Multi-output results are frozen tuples with NumPy field names: `[Q, R]`, `[eigenvalues, eigenvectors]`, `[U, S, Vh]` and `[sign, logabsdet]`. `qr(a, "r")` and `svd(a, { compute_uv: false })` return one expression. The LAPACK-specific `"raw"` QR mode and unknown SVD options fail with `NMATH_INDEX_INVALID`; `hermitian: true` is accepted and runs the general SVD. Declarations require square matrices for Cholesky, `eigh`, `eigvalsh` and `slogdet`, reject float16, map complex results to their real dtype through `LinalgRealResult`, and keep literal batch and row/column sizes where NumPy's shape rule makes them known.

`linalg.norm(x, ord?, axis?, keepdims?)` follows NumPy's dispatch: without `axis`, an undefined `ord` flattens the input and other orders require one or two dimensions; one axis selects a vector norm and two axes a matrix norm. The package moves the selected axes to the end with a transpose and reshapes for `keepdims`. `linalg.matrix_rank(A, { tol, rtol, hermitian })`, `linalg.pinv(a, { rcond, rtol, hermitian })`, `linalg.cond(x, p?)` and `linalg.matrix_power(a, n)` compose existing lazy nodes in NumPy's order: the rank counts singular values above `max(s) * max(M, N) * eps` or the given threshold and returns `int64`; the pseudo-inverse uses the reduced SVD of the conjugate with NumPy's `1e-15` default cutoff; the condition number divides extreme singular values and turns NaN into infinity unless the input has NaN; matrix powers use NumPy's binary multiplication order and keep integer and bool dtypes for non-negative powers. `cond` orders other than 2 and -2, and one-dimensional `matrix_rank`, fail with `NMATH_INDEX_INVALID` or `NMATH_SHAPE_MISMATCH` and remain targets. A singular matrix's condition number is rounding noise; NMath can return infinity where NumPy returns a large finite value, and both satisfy NumPy's `> 1e15` test criterion.

`linalg.eig(a)` returns `[eigenvalues, eigenvectors]` with NumPy field names and `linalg.eigvals(a)` returns the eigenvalues. `LinalgComplexResult` maps single precision to complex64 and other inputs to complex128; results are always complex, unlike NumPy's data-dependent real result for real input with all-real eigenvalues. Eigenvalue order is unspecified.

Linalg declarations preserve batch/result shape and reject known nonsquare matrices and incompatible solve core dimensions. FFT declarations preserve unchanged dimensions for omitted or positive literal axes and axis `-1`. Real-transform axis lengths and other negative/dynamic axis inference remain conservative; exact inference for those forms remains a target. These APIs do not establish full linear-algebra or FFT family coverage.

### Strings and temporal storage

`str` arrays accept nested JS strings. `ArrayOptions.stringWidth` selects a positive width in Unicode scalar values; omission infers the longest input width, with a minimum of one. Creation rejects input that exceeds an explicit width. `item()`, rank-zero `compute()` and `toArray()` return JS strings. Use `toArray()` for string export; strings have no typed-array export. Unpaired UTF-16 surrogates are rejected rather than replaced silently.

`new Temporal(ticks, unit, dtype)` is an immutable scalar whose `ticks` are a signed 64-bit bigint, whose `unit` is a supported NumPy unit or positive multiple, and whose `dtype` is `datetime64` or `timedelta64`. `isNaT` identifies the minimum signed 64-bit tick. Implicit numeric conversion throws. Only datetime scalars expose `toDate()`, an explicit conversion to JS Date precision and range; NaT becomes an invalid Date and out-of-range dates throw.

Temporal arrays accept BigInt64Array ticks or nested Temporal scalars. `ArrayOptions.unit` selects the array unit, defaulting to `ns`; Temporal inputs must match its kind and unit. `item()`, rank-zero `compute()` and nested `toArray()` return Temporal scalars. `toTypedArray()` exports exact ticks without converting units. Arrays and expressions expose `unit` and `stringWidth` as applicable. `astype(dtype, {unit?, stringWidth?})` requests an explicit conversion. Basic and advanced indexing, context copies and NPY/NPZ preserve metadata. `full(shape, value, dtype, metadata?)` supports the same storage families; a Temporal fill value supplies its unit when metadata omits one.

String and temporal operation support and current limitations follow the runtime contract. Dtype inference distinguishes datetime subtraction from addition, preserves duration mean, and rejects known invalid combinations. pandas/Polars selection, boolean filtering and wrapper conversion preserve these columns; specialized string and time-series APIs remain compatibility targets.

### Shape transformations

`numpy.transpose(a, axes?)` and `a.transpose(axes?)` create lazy axis permutations. Omitted axes reverse the axis order; explicit axes form a complete permutation and may use negative indexes. `numpy.reshape(a, shape, options?)` and `a.reshape(shape, options?)` use C logical element order. Options are `{order?: "C", copy?: boolean | null}`. Omitted/null `copy` shares storage when possible, `true` forces independent storage, and `false` rejects a copy-required layout. Other orders and unknown options fail explicitly. `-1` infers one dimension; other negative dimensions, repeated `-1`, incompatible element counts and ambiguous empty inference fail with `NMATH_SHAPE_MISMATCH`. A dimension must fit the package's unsigned 32-bit shape transport.

Both APIs preserve dtype descriptors, string width, temporal units and context. Compatible basic-index/transpose/reshape chains return live views after `compute()`, including regular stepped and reversed layouts. Changes through either view remain visible; disposing one handle retains storage needed by another. Copied and computed results use execution-start snapshots and independent executions. CPU scheduling, cancellation, budgets and atomic writes follow the existing runtime contract. GPU requests for these nodes reject before admission without fallback.

Ordinary TypeScript infers axis permutations and compatible literal reshape dimensions, including the inferred `-1` dimension, using decimal arithmetic rather than array-sized tuple types. Known invalid dimensions, element counts and axis permutations fail declaration checks. Dynamic dimensions retain known result axes, dtype and rank; a dynamic axes list retains the source rank with unknown axis sizes. Scientific-notation dimensions and unknown-rank arrays defer size checks to runtime. F/A traversal, alternate scalar shape arguments and broader upstream signatures remain compatibility targets.

### Polynomial JS adaptation

The NumPy entry point exports `polyval(coefficients, points)` for descending coefficients and `polynomial.polynomial.polyval(points, coefficients, { tensor?: boolean })` for ascending coefficients. Both operands are explicit-context NMath arrays or expressions. Tensor defaults to true. Native execution, integer coefficient conversion, empty coefficient handling, non-finite initialization and memory accounting follow the [runtime polynomial contract](crates-nmath-runtime-contract.md#polynomial-evaluation). Unknown options and nonboolean tensor values reject rather than being ignored.

Types retain promoted dtype and known output dimensions. Ascending tensor evaluation appends the points' shape after the polynomial batch shape; non-tensor evaluation broadcasts them. Statically empty ascending coefficients, rank-zero descending coefficients and statically incompatible broadcast shapes reject. Dynamic coefficient lengths retain the descending empty/nonempty result alternatives. Both APIs use the shared lazy `compute` behavior, CPU scheduling and snapshots; neither evaluates coefficients in JavaScript. Scalar JS values must be wrapped as rank-zero context arrays. Polynomial classes, fitting, roots, coefficient arithmetic, other bases and additional NumPy polynomial APIs remain support targets.

### Polynomial derivative adaptation

The NumPy entry point exports `polyder(coefficients, m = 1)` for descending rank-one arrays and `polynomial.polynomial.polyder(coefficients, { m?: number, axis?: number, scl?: number | Complex })` for ascending coefficients. Ascending options default to order one, axis zero and scale one. Orders are nonnegative safe integers; axes are safe integers normalized against the coefficient rank (or rank one for scalar ascending coefficients). Fractional and string legacy orders reject rather than applying Python's coercion. Unknown options reject. Scales are scalar numbers or `Complex`; array-valued scale broadcasting remains a support target.

Both forms use the native derivative graph and its [dtype, shape, snapshot, memory and cancellation rules](crates-nmath-runtime-contract.md#polynomial-derivatives). Legacy order zero preserves the original array/view storage. Ascending order zero copies and converts boolean/integer inputs to float64. Shape types retain rank, unchanged dimensions, literal derivative lengths and dtype promotion. Dynamic orders make only the selected axis size dynamic; dynamic axes preserve rank. Optional and union options retain their default/result alternatives. Statically invalid axes, negative/fractional orders and known legacy ranks other than one reject at type checking. Dynamic values validate at runtime. Integration, polynomial classes, fitting, roots and other bases remain compatibility targets.
